# 外部消息编辑的身份与恢复

编辑按钮读取 OPL 已保存的精确用户消息身份；显示入口不启动 CLI，也不依赖当前模型仍在目录中。实际发送由 Host 统一检查权限、空闲状态、历史版本和底层身份，并持久记录修改意图。Client 只投影该状态，历史暂不可读时保留草稿并有限补读，不自动发送。

OpenCode/Kilo 的失败回复可能没有成功完成时间。恢复必须核对原请求、已结束的本地轮次和工具、自有 CLI 退出、官方空闲状态及两次稳定历史，不补造厂商完成时间，不按正文猜消息。首条没有前文时可以明确创建空底层会话；后续消息必须完整保留精确前文身份。

StepCode 使用官方 RPC fork，并校验保留记录、模型和推理设置。懒持久化的空分支保留当前连接，写入后才登记可恢复身份；替换 prompt 仍只由共享 Host 提交一次。旧记录缺少原生 input ID 时拒绝猜配。MiniMax 的官方 load 响应可以省略请求中的 sessionId，只有显式返回冲突身份才拒绝。

读取编辑历史时，先完成官方会话加载，再计算记录版本和核对缓存；加载补回上下文统计可刷新缓存。历史读取期间的用户消息身份变化仍会使本次读取失败。

自有 ACP 退出触发的 bridge cleanup 与随后 disconnect 共用同一个 Promise；必须等清理结束，后续调用仍收到原失败。旧连接的收尾不能删除后来建立的连接。启动、取消、监听释放、历史变化和请求结果不确定均保留明确状态，不重放请求、删除旧分支或撤销文件。

聚焦测试覆盖身份冲突、失败后重复编辑、冷恢复、取消和清理失败。真实官方 Desktop 验证 StepCode 工具与重复编辑、Pi 旧失败消息回填、OpenCode 配额失败后编辑恢复，以及 MiniMax 工具、两轮编辑和重启后的用量显示；不可用模型的失败恢复不代表其云请求成功。
