# 跨 Harness 团队接入

官方角色预设可以绑定精确执行组合，在官方 Subagent/Team 的成员会话中使用 DSH、Codex 或 Claude Code。官方插件和应用资源保持原样。

## 配置与状态职责

官方保存角色、人设、Skills、成员身份、消息、权限与团队任务板。OPL 保存预设到组合的引用以及官方会话到外部会话的关联；组合继续引用模型来源，凭据留在来源服务。已有交付验收记录继续使用原 ID，不复制官方团队状态。

## 插件与使用

| 插件             | 负责内容                                         | 依赖                             |
| ---------------- | ------------------------------------------------ | -------------------------------- |
| OPL DSH 基础增强 | Gateway、首启、更新与通用体验                    | 官方 DSH                         |
| OPL 执行组合     | 模型与 Harness 组合、CLI、外部会话及共享执行记录 | 官方 DSH；模型来源由对应插件提供 |
| OPL 跨引擎协作   | 角色绑定、官方工具桥、跨引擎交付与验收入口       | OPL 执行组合                     |

1. 在官方 Agent 预设中建立开发者、审查者等角色，配置人设、Skills 和所需的官方协作工具。
2. 在「执行与组合」准备已就绪的 Codex、Claude 等精确组合。
3. 在「协作与自动化 → 角色与执行」分别绑定角色与组合；留空表示跟随会话设置。
4. 使用官方团队入口创建相应预设的成员。绑定作用于新会话和新成员；已有会话继续原组合。组合声明的只读限制可以收紧继承权限，选择组合不会扩大成员权限。

外部 CLI 通过 `opl-harness` MCP 的 `dsh_*` 工具调用官方成员通信和任务能力。角色需要的工具由官方预设控制；OPL 不替角色增加未获准的工具。

## 接入链路

官方 local spawn/fork 创建并恢复真实成员会话。OPL 在公开 `agent/created` 事件中选择组合，以 `llm/stream` 转接该成员的执行；官方成员消息进入同一外部会话。人设、团队规则与运行上下文从公开系统提示接口装配。Codex 使用官方 app-server 的 developer instructions，Claude 使用官方 SDK 的 system prompt 扩展。

每个外部会话持有独立 MCP capability，调用者身份由 Host 的会话关联确定。工具列表来自该成员实际获准的工具集合，执行经过官方 `tools.resolve`、`tools.execute` 和权限检查。普通会话标题接口不用于团队成员；成员取消使用官方 Agent 生命周期。

组合、会话和原交付记录沿用原 ID 与数据位置。协作插件关闭后，执行组合继续运行；基础增强关闭后，执行组合仍可使用其他已适配的来源。多包更新在停止状态下完成，保留禁用选择；旧配置字段一次迁移到各自 owner，保存原文件备份，保留目标已有显式设置。

## 验证状态

2026-11-15 已在未修改的 macOS 官方 DSH `0.2.2-rc.3` 中完成以下实际验证：

- Codex 官方成员创建、真实文件写入、向 lead 发信、冷启动后继续同一外部会话。
- DSH 协调者、Claude 审查者和 Codex 开发者混合协作；Claude 领取并完成官方任务，再发信驱动原 Codex 成员续作。
- 官方取消中止真实 Codex 的等待任务，阻止后续写入；取消后继续原外部会话。
- 官方插件列表读取三个包的名称、说明、图标和离线详情；角色绑定经真实 Client 保存并恢复。
- 独立启停、关闭基础增强后使用另一模型来源、保留绑定和外部身份，以及停止状态下更新保留禁用选择。

源码类型检查、构建、全量测试和模块边界检查已通过。Windows 官方桌面资格由现有兼容工作流验证；真实模型混合团队的上述记录来自 macOS。合入、发布和用户日常安装的更新另有交付边界。

可复现入口为 `scripts/qualification-mixed-team.mjs`。它使用新隔离目录，只读取所需模型配置和凭据引用，不修改日常 profile；阶段可用 `--phases=` 指定。真实模型验收需要本机 Codex、Claude Code 和对应模型来源已经就绪。
