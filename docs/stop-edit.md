# 编辑消息

对话的“编辑消息”在原对话内替换重发，首条消息也不创建分支。每条可编辑的用户消息在悬停或键盘聚焦时，右下角显示与“复制”并列的编辑图标；点击该图标即选择这条消息，原文回填到官方输入框。选择和修改草稿时，聊天记录保持原样。点击普通发送按钮后，所选消息及其后续回复从当前聊天视图和下一次模型输入中移除，修改后的消息在同一个会话中发送。

输入栏右侧的关闭图标可取消编辑，保留原聊天记录并恢复选择前的草稿。切换对话和新建对话不会继承另一条对话的编辑目标。重新加载后，原会话的编辑目标与官方草稿一起恢复。

编辑需要会话已经停止且没有待发送消息。带附件的消息、已经压缩或替换的消息暂不提供编辑。原生子任务和受协作台账管理的任务不使用该入口。Codex、Claude、Grok、MiniMax、ZCode、OpenCode、Kilo、Kimi、Pi、Pool 和 StepCode 按精确底层消息身份提供同一入口。底层需要分支时由后台接替，侧边栏仍保留同一个 DSH 会话。旧记录缺少精确身份时不按文本或条数猜测；首条消息无需保留前文，可在明确编辑发送时分配新的底层空会话。后续消息只有前文映射完整时才能编辑。旧版生成的编辑分支及其日志保留可读。

编辑入口读取已保存的消息身份，不因当前模型下架或重新连接 CLI 而消失。发送时仍核对当前模型、权限与底层历史；已移除的模型不会被自动替换。临时历史读取失败保留草稿和选择，原因放在悬停提示中，可点击重试；自动补读最多两次，不自动发送。会话结束或真实历史就绪时刷新入口，逐字输出不触发重复读取。

发送使用官方空闲维护机制与公开会话表面替换接口，输入校验完成后再提交替换并刷新持久记录；原始事件仍保留用于审计，不从磁盘删除会话日志。只有带 OPL 编辑标记且对应新消息已落入日志的范围会从聊天视图隐藏，普通压缩不隐藏用户原聊天记录。文件内容始终保持原样，不撤销已经执行的工具。

“通用设置 → 轮次与步数”可选“当前对话”或“历史累计”，默认使用当前对话。当前对话排除被编辑替换的执行记录，历史累计保留全部执行记录。两者均以已结束步骤计数：同一轮的多个步骤只算一轮，失败或取消后已结束的步骤仍计入；尚未结束的步骤不计入。分页、压缩和重启不改变计数。该选项只改变轮次与步数，耗时和 Token 用量仍使用官方累计统计。

若选择后对话发生变化，发送会要求重新选择。传输或持久化结果不确定时不会自动再次替换，也不会把它描述为未生效；原始记录保留，未确认的替换阻断后续模型请求。

如果替换已经写入，但模型准备失败或取消发生在新消息落盘之前，在会话空闲且没有待发送消息时，入口显示“重试未确认的编辑”。运行期间不显示恢复按钮；读取状态期间收到会话变更会重新读取，避免保留发送中间状态。该操作使用持久记录中的原请求与原文本重新提交缺失的消息，不再次替换历史、不自动重派。读取状态或重启不会发送请求；内容或身份不符仍拒绝恢复。

外部编辑先持久记录底层修改意图与结果，再保存接替身份并提交一次替换消息。断线或重启后结果不明的操作保持阻断，不自动重放回退或模型请求；底层旧分支保留，文件不回退。ZCode 首条编辑会新建官方 ZCode 会话，复用当前模型、工作目录和权限档位；当前 DSH 会话身份保持不变。

限流、额度不足等明确结束的失败不取消编辑能力。系统核对失败请求、底层消息身份与当前历史后恢复编辑入口；尚未发送到 Harness 的替换消息也可以再次修改。Pi 未落盘的空分支在用户再次编辑发送时重新分配底层空会话，侧边栏身份保持不变，不重发旧请求。结果未知、身份不符或历史无法核对时继续保留阻断。

OpenCode 和 Kilo 的失败记录不必具有成功回复的完成时间。系统等待自有 CLI 退出，复核空闲状态、工具终态和稳定历史后才允许分叉，不补写厂商完成时间。新请求返回的精确用户消息 ID 及时保存，最终历史回读失败也不丢弃该身份。StepCode 使用官方 RPC 分叉，保留目标之前的完整记录和原推理设置；首条分叉尚未落盘时保持当前连接，替换消息只由统一发送流程提交一次。

旧会话编辑重发会先恢复实际连接，缓存中的编辑目标不能代替连接检查。如果底层分支和接替身份已经保存、替换消息尚未提交，重新打开对话可再次选择原消息发送；这不会重放上次请求或再次回退历史。旧版缺少原消息序号的记录，仅在当前对话只有一条用户消息且底层已确认是空分支时提供恢复入口。

已授权的本机控制连接可以通过 `oplExecution/message-edit-state` 读取精确目标，再调用 `oplExecution/message-edit-send`。自动化和输入框共用相同的空闲检查、历史版本与持久事务，不绕过会话权限或恢复限制。
