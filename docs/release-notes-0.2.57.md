官方 DeepSeek Harness：`{{OFFICIAL_VERSION}}` · OPL 增强：`{{VERSION}}`

本次更新扩展了模型与图片输入支持，并改进了 Gateway 模型目录、CLI 检测和消息编辑恢复；不支持的图片输入会在发送前明确拒绝。

### 变更

- Kilo Code 新增 OFM 的 Kilo Crouton Alpha 模型。
- 支持符合模型来源和 CLI 能力条件的图片输入，保留文字与多张图片的顺序及官方附件引用；编辑图片消息时可保留原图片。
- 修复 Gateway 发现及模型目录同步问题；目录读取失败时保留已有模型配置，并更清楚地区分凭据、认证、网络和设置等问题。
- Harness 设置区分“已发现”和“验证通过”；检测已有 CLI 不再依赖 npm，并保留用户指定的启动入口，另行展示发现的其他入口。
- 消息编辑的重试与未确认操作恢复入口移至对应消息操作；MiniMax 退出仍在处理时会显示等待状态。
- AWS/Kiro Gateway 默认地址与 Opus 5.5 兼容设置可迁移；用户自定义地址、凭据引用和显式兼容设置保持原值。

### 已知限制

- 图片输入仅对模型来源已声明支持且 CLI 能力已确认或符合兼容条件的组合开放；其他组合不会发送图片。
- 图片编辑要求原附件引用及底层消息身份可核实；Grok 历史无法可靠确认图片数量时不提供图片消息编辑。
- 本次图片输入不扩展为音频或通用文件上传。
- 官方桌面及其候选阶段以以上实际版本为准；开发 API 依赖与桌面 feed 分别记录。
- 本地模型 fixture 证明协议、工具和持久化链路，不代表真实 Gateway、外部模型质量或全部 Harness 组合已验收。
- Windows 受限 token 下的 Git Bash 外部程序仍有限制；验收的真实 Git Bash 工具路径使用显式授权的完整访问权限，不自动执行 ACL 修复。
- 新功能的适用范围与限制见对应功能文档及提交；直接打开官方桌面不会运行外部 OPL 更新器。
