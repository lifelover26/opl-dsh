# Auto Review 工具审批

“执行与组合 → 工具审批”默认关闭。启用后，在会话权限中选择 Auto 才会使用工具审查；保存设置不会改变已有会话的权限。

## 审查路线

DSH 原生会话和 ZCode 默认使用 OPL Gateway 的专用模型 `codex-auto-review`，与聊天模型及其推理强度分开。专用路线单独配置，不依赖普通聊天模型列表。也可以在设置中显式选择一个已注册的原生无工具 LLM 作为固定审查模型。

BambooNode StartLux 在 Auto Review 中作为独立的“决策模型”路线选择，不与普通 reviewer 混列。它使用 Bamboo 的同步 decisions API，将审查策略和冻结事实转换成一个联合选择题；路线不提供工具、不绑定执行会话，也不会出现在普通聊天模型列表。Windows API Key 只保存在 Credential Manager。缺少 Key、请求失败、结果缺失、未知选择或不确定结果均拒绝放行。

同一下拉列表也提供 **OpenCode · Jev / Jev 1.13 Free**，无需配置个人 API Key。它调用 OpenCode 发布的 System One 决策接口，不经过 OFM 的聊天转发，也不进入普通聊天列表。选择概率及置信度都达到 0.9、结果字段完整且一致时才接受允许结论；其余结果拒绝放行。免费通道的限额或不可用状态会使本次审核失败，不自动换路线。详见 [Jev 决策模型](jev-auto-review.md)。

升级已有 profile 时，套件通过官方设置接口补入缺失的隐藏审查 provider，保留已有聊天 provider 和模型列表。已有审查 provider 不覆盖；配置冲突时保留原配置，审查路线不可用就拒绝送审。

审查请求不提供工具；传输携带被审查会话身份与审核用途，供供应商选择对应路由，不创建执行会话。路线缺失、请求失败、超时、结果不完整或不能保存时不放行；不会临时换成聊天模型。原有执行检查仍生效。

## 外部 Harness

ZCode 的 Auto 新对话使用官方 `build` 模式，将其权限询问交给专用审查模型。宿主核对原生会话、精确调用 ID、ACP 会话、连接代次、轮次、结构化工具参数及持久用户指令，保存审核结果后再次核对。绑定不完整时保留人工审批，已认领的审核失败则拒绝。

Codex 与 Claude 使用各自官方审核接口，不经过 DSH 的审查模型。未经验证的其他 Harness Auto 模式拒绝启动；它们已有的普通权限流程保留。

外部对话创建时保存审核模式。ZCode 的完整权限对话保持 `yolo`，Codex/Claude 的完整权限对话保持官方直接执行模式。在旧对话中改变审核模式后须新建对话，不会在恢复时悄悄改变原权限。

## 设置与记录

开关、路线和预算点击保存才生效。过期 revision 或任一项目有活动任务时拒绝修改。保存回执丢失时先重新读取，不重发结果不确定的保存。

停用前先切换空闲 Auto 会话的权限；停用不会把它们改成完全权限。卸载期间等待中的审核保持拒绝保护。

审核输入、结论与 Session、turn、call 关联保存在当前 profile 的官方 `opl_auto_review` storage-domain。重启读取原记录，不执行历史工具或重放审查。
