# 第三方模型插件

OPL 安装器通过官方插件管理器接入原版 [Our Free Model](https://github.com/Ebony-Vinyl/dsh-our-free-model)。首次安装使用官方 `v2.8.3` 完整发布包，验证固定 SHA-256 后保存到 profile 的 `vendor/` 目录，供安装和后续修复使用；不重新打包、不修改源码，也不裁剪账号渠道、工具输出压缩、自动续跑和设置页面。下载或摘要校验失败时停止安装，不使用旧版源码包替代。

OPL 为 OFM 使用 profile 内的独立程序目录，通过官方插件管理器以相对 `link:` 依赖登记。OFM 页面保留原版检查更新、升级与热重载功能；程序文件由 OFM 自己更新，pnpm 只管理链接。OPL 重装保留该目录和已升级版本，不用安装器固定版本覆盖它。插件的数据、账号和其他设置仍由 OFM 在原数据位置管理。

停机安装时，安装器只迁移能够确认属于本套件的 OFM 归档安装，保留用户指定的其他来源和停用状态。升级失败时使用原版 OFM 的恢复流程；安装迁移失败则恢复原依赖。用户自行配置的宿主管理模式不会被安装器自动撤销。

## 模型与 Harness

OPL 从官方 LLM 注册表读取所有插件公开的 Provider 和模型，以原始 `provider` 与 `model` 保存组合引用。模型目录不复制到 OPL 配置，密钥也不导入 OPL Gateway。

已适配的模型按精确 Provider、模型 ID 与适配器选择默认 Harness；没有外部配对的模型使用 DSH，已有自定义默认组合优先。OFM 首选配对集中列在[外部 Harness 适配](harness-adaptation.md#our-free-model-组合)，不会因为模型同名就替换渠道。账号渠道尚未登录、上游不提供或被插件关闭的模型，以插件实际公开的目录为准。

插件的 `combo:` 降级与轮换链由 OFM 管理，不作为可执行模型加入 OPL 对话选择器；外部 Harness 需要绑定已适配的具体模型。

DSH 组合执行官方 DSH Agent 循环和工具；外部组合执行所选 Harness 的循环和工具。外部 Harness 必须有适配器支持精确模型来源；原样接入模型插件不代表任意模型可在任意 Harness 上执行。

## 管理入口

在设置中的 **OFM 模型服务** 页面管理免费模型、EAC、账号渠道、聚合来源、虚拟路由与用量。OPL 的 **执行组合** 负责模型与 Harness 的绑定，对话选择器负责选择组合。

第三方模型插件沿用这一条官方注册表接入路径；OPL 不另建每个供应商的模型列表、账号池或请求适配器。

来源插件可以通过 Host 的显式路由注册接口适配已支持自定义端点的官方 Harness，详见[外部 Harness 适配准备](harness-adaptation.md)。OPL 已通过该接口注册 OFM 的精确配对；新增未适配模型不会仅凭名称自动获得外部 Harness 支持。
